# Design-Review Web-Frontend, 2026-08-28

Gegenstand: `web/` (index.html, css/terminal.css, js/app.js, js/pages/*.js,
js/charts.js, js/treemap.js, js/studies.js), Backend `api/server.py`.
Auftrag: Bestandsaufnahme plus umsetzbare Vorschlaege. Kein Umbau in diesem
Durchlauf.

## Verifikationsstand

Das Frontend lief waehrend der Pruefung unter `python api/server.py`
(uvicorn, Port 3000, Startkonfiguration `terminal-api` in `.claude/launch.json`).
Alle API-Routen antworteten mit 200.

Screenshots waren in dieser Umgebung nicht verfuegbar: die Browser-Vorschau
komponiert keine Frames, `computer:screenshot` lief in den Timeout. Jeder
Befund unten ist deshalb per DOM-Inspektion (`getComputedStyle`,
`getBoundingClientRect`, Accessibility-Tree) und per Code-Lesen belegt, nicht
per Bild. Wo eine Aussage nur ein Bild belegen koennte, steht sie nicht drin.

Gemessen wurde im laufenden Dokument: fuer jeden Textknoten die effektive
Vordergrundfarbe nach Alpha-Kompositing gegen den naechsten deckenden
Hintergrund, dazu Schriftgroesse und Gewicht, und daraus das WCAG-2.1-Verhaeltnis
gegen die passende Schwelle (4.5:1 normal, 3:1 ab 24px bzw. ab 18.66px fett).

Der Impeccable-Detektor lief degradiert: die HTML-Parser-Module
(htmlparser2, css-select, css-tree, domutils) fehlen auf dieser Maschine, der
Regex-Rueckfall wertet weder Custom Properties noch berechneten Kontrast aus
und lieferte eine leere Liste. Das ist kein Freispruch, sondern ein
Nicht-Ergebnis. Die Live-Messung ersetzt ihn hier vollstaendig und ist fuer
diese Codebasis ohnehin das bessere Werkzeug: das gesamte Markup entsteht erst
zur Laufzeit als String aus JavaScript, eine statische Datei gibt es nicht.

## Befund 1, der wichtigste: das helle Thema faellt flaechig durch WCAG AA

Die Alpha-Leiter der Textstufen wurde auf dem dunklen Grund kalibriert und
unveraendert auf den hellen uebernommen. Das kann nicht aufgehen. Auf dunklem
Grund komponiert ein helles `--ink` gegen ein dunkles `--bg` und gewinnt
Kontrast schnell; auf hellem Grund komponiert ein dunkles `--ink` gegen ein
helles `--bg` und gewinnt ihn langsam. Dieselbe Zahl hinter dem Komma bedeutet
in den beiden Themes etwas voellig anderes.

Gemessen, `rgba(var(--ink), a)` gegen `--bg`:

| Alpha | dunkel (`--ink` 234,230,220 auf `#0B0B0A`) | hell (`--ink` 32,30,25 auf `#F4F1EA`) |
|---|---|---|
| .70 | 7.94 | 5.80 |
| .66 | 7.14 | 5.10 |
| .62 | 6.40 | 4.50 |
| .60 | 6.05 | **4.23** |
| .55 | 5.23 | **3.65** |
| .50 | 4.49 | **3.16** |
| .45 | 3.84 | **2.75** |

`.60` und `.55` sind die beiden meistgenutzten Textstufen des Terminals. Beide
sind im hellen Thema unzulaessig. Anteil der Textknoten, die im hellen Thema
AA verfehlen, je Route gemessen:

| Route | geprueft | Verstoesse | Anteil |
|---|---|---|---|
| markets | 4091 | 2403 | 58.7 % |
| whale | 363 | 246 | 67.8 % |
| research/live-runs | 781 | 471 | 60.3 % |
| risk | 83 | 47 | 56.6 % |
| overview | 234 | 114 | 48.7 % |
| flow | 2079 | 992 | 47.7 % |
| backtester | 44 | 21 | 47.7 % |
| alerts | 351 | 160 | 45.6 % |
| traders | 667 | 241 | 36.1 % |
| research/microstructure | 1001 | 241 | 24.1 % |
| research/methodology | 52 | 12 | 23.1 % |
| research/pilot | 299 | 30 | 10.0 % |

Im dunklen Thema ist dieselbe Messung praktisch sauber: 3 von 161 Knoten auf
der Startseite, und die drei liegen bei 4.49 gegen 4.50, also auf der
Rundungskante.

Dazu die Rollenfarben des hellen Themas gegen den Seitengrund `--bg`
(`web/css/terminal.css:63-98`). Gegen `--panel` bestehen sie alle, aber sehr
viele Beschriftungen sitzen direkt auf `--bg`:

| Token | heute | gegen `--bg` | Status |
|---|---|---|---|
| `--cat-gold` | `#8F7430` | 3.95 | faellt durch |
| `--cat-teal` | `#3F7F72` | 4.15 | faellt durch |
| `--muted` | `#767264` | 4.27 | faellt durch |
| `--cat-blue2` | `#5C7194` | 4.39 | faellt durch |
| `--pos` | `#2E7D4F` | 4.47 | faellt durch |
| `--cat-rose` | `#9C5B72` | 4.48 | faellt durch |
| `--warn` | `#A85A14` | 4.50 | Kante |
| `--neg-soft` | `#9E5D50` | 4.50 | Kante |

Dass `--pos` durchfaellt, ist der teuerste Einzelposten: das ist die Farbe
jeder positiven Zahl im ganzen Terminal.

### Der Fix, live gemessen

Die Ursache sitzt an einer Stelle, nicht an tausend. Im hellen Thema muss
`--ink` auf reines Schwarz, damit die vorhandenen Alphas legal werden; nur
`0,0,0` schafft bei `.55` die 4.5 (4.62). `8,7,5` kommt auf 4.36, `12,11,8`
auf 4.23. Dazu acht Rollenfarben um 2 bis 9 Prozent abdunkeln.

Ich habe den Patch im laufenden Dokument eingespielt und dieselbe Messung
wiederholt:

|---|---|---|
| markets | 58.7 % | **0.0 %** |
| flow | 47.7 % | **0.0 %** |
| alerts | 45.6 % | **0.0 %** |
| research/methodology | 23.1 % | **0.0 %** |
| research/pilot | 10.0 % | 0.7 % |
| research/microstructure | 24.1 % | 1.2 % |
| research/live-runs | 60.3 % | 2.0 % |
| backtester | 47.7 % | 2.3 % |
| risk | 56.6 % | 6.0 % |
| whale | 67.8 % | 7.4 % |
| traders | 36.1 % | 7.6 % |
| overview | 48.7 % | 9.0 % |

Elf geaenderte Zeilen in `web/css/terminal.css`, kein JavaScript angefasst.
Der Rest sind ausschliesslich Aufrufstellen mit `.5` und `.45` plus ein
`rgba(var(--pos-rgb), .75)` auf der Whale-Seite: das sind Einzelstellen im JS
und gehoeren in die naechste Runde, nicht hierher.
